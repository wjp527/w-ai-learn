## 一、背景与目标

### 1.1 背景

V1 已实现完整学习闭环，但存在以下局限：

- 用户以匿名会话学习，关闭小程序后数据不可追溯
- 「题库」「我的」Tab 仅为 UI 占位，数据为 Mock
- 报告页提示「记录已保存」，实际未持久化
- 无法跨设备同步学习进度与历史

### 1.2 本次扩展目标

在**不破坏 V1 核心闯关流程**的前提下，引入用户身份与学习数据持久化，使用户能够：

1. 以微信身份登录并识别用户
2. 查看个人学习统计与历史记录
3. 管理 AI 生成的题目集（题库）
4. 从多个入口快速继续或重复练习

### 1.3 设计原则（需求层面）

- **渐进交付**：按批次上线，每批可独立验收
- **向后兼容**：未登录用户仍可匿名闯关（与 V1 行为一致）
- **对齐原型**：有原型图的页面严格按原型交互与信息架构实现
- **YAGNI**：原型标注「P1」且非用户体系前置项的功能，本次不做
- **关系型持久化**：用户、题目集、学习记录等关系型数据使用 **MySQL** 存储（方案设计文档中细化）

## 三、用户角色与场景

### 3.1 用户角色

| 角色 | 说明 |
|------|------|
| 已登录学生 | 微信授权登录，学习数据通过 MySQL 持久化至服务端 |
| 匿名访客 | 不登录或登录失败，仅可使用 V1 闯关流程，无历史同步 |

### 3.2 核心场景

**场景 A：首次进入并完成学习**

> 学生打开小程序 → 完成登录 → 粘贴笔记出题 → 闯关答题 → 在「我的」看到刚完成的记录

**场景 B：回顾历史学习**

> 学生进入「我的」→ 查看学习记录列表 → 点击进入某次详情 → 查看错题与 AI 总结

**场景 C：重复练习**

> 学生进入「题库」→ 选择历史题目集 →「再练一次」或「开始闯关」→ 进入答题流程

**场景 D：中断后继续**

> 学生上次未完成答题 → 在首页「继续上次」看到进度 → 点击继续

**场景 E：匿名使用**

> 学生拒绝/未完成登录 → 仍可闯关 → 报告正常展示 → 但不写入个人历史

## 四、需求批次与优先级

整体按 **6 个批次** 交付，批次间有依赖关系，须按顺序实施。

```
批次 1 用户登录
    ↓
批次 2 用户信息
    ↓
批次 3 学习记录（写入 + 列表）
    ↓
批次 4 学习记录详情
    ↓
批次 5 题库
    ↓
批次 6 流程串联与体验收尾
```

---

### 批次 1：用户登录（P0 · 最高优先级）

**目标**：建立用户身份，后续所有个人数据依赖本批次。

#### 功能需求

| ID | 需求 | 说明 |
|----|------|------|
| U1-01 | 微信登录 | 用户进入小程序后，可完成微信身份登录 |
| U1-02 | 登录态维持 | 登录成功后，本次及后续访问可识别为同一用户，无需每次手动登录 |
| U1-03 | 登录失败降级 | 登录失败不阻断主流程，用户可匿名闯关 |
| U1-04 | 登录状态感知 | 前端可判断当前是否已登录，用于「我的」等页面展示差异 |

#### 业务规则

- 登录为**静默优先**：进入小程序时自动调用 `wx.login` 换取身份，不强制弹窗打断闯关主流程
- 头像昵称授权为**按需触发**：在「我的」页由用户主动授权（微信 `chooseAvatar` + `nickname` 输入能力），不阻断主流程
- 同一微信用户多次登录应识别为同一账号，不重复创建
- 未登录状态下，现有 V1 接口行为保持不变

#### 验收标准

- [ ] 用户首次打开小程序，后台完成 openid 绑定（或明确记录登录失败原因）
- [ ] 用户关闭并重新打开小程序，仍识别为已登录状态（在登录态有效期内）
- [ ] 登录失败时，用户可正常完成一次完整闯关
- [ ] 「我的」页可区分「已登录」与「未登录」状态（文案或引导差异）

#### 原型对应

- ⑪ 我的页副标题「累计闯关 N 次 · P1 登录后同步」→ 登录后应显示真实统计

---

### 批次 2：用户信息（P0）

**目标**：在「我的」页展示真实用户身份，替代 Mock 昵称与头像。

**依赖**：批次 1

#### 功能需求

| ID | 需求 | 说明 |
|----|------|------|
| U2-01 | 获取用户信息 | 已登录用户可获取自己的基本资料 |
| U2-02 | 展示用户头像 | 「我的」页顶部展示头像（微信头像或默认形象） |
| U2-03 | 展示用户昵称 | 「我的」页展示昵称，风格对齐原型「怕踢学渣 No.9527」 |
| U2-04 | 编辑显示昵称 | 用户可修改对外展示的昵称 |
| U2-05 | 未登录引导 | 未登录时展示默认形象，并提供「点击登录」或等效引导 |
| U2-06 | 头像昵称授权 | 用户可通过微信头像选择器与昵称输入组件更新资料 |

#### 业务规则

- 新用户首次静默登录时，若未授权头像昵称，系统分配默认昵称（如「学渣 No.xxxx」）
- 头像获取失败时使用现有 IP 形象（小衰神）作为兜底
- 昵称长度 1～20 字，不允许纯空白；敏感词过滤可后置
- 用户自定义昵称优先级高于微信昵称

#### 验收标准

- [ ] 「我的」页不再展示写死的 Mock 数据
- [ ] 已登录用户看到自己的头像与昵称
- [ ] 用户可修改昵称并即时生效
- [ ] 未登录用户看到默认形象与登录引导，不展示虚假统计数据

#### 原型对应

- ⑪ 我的页顶部用户区域（头像 + 昵称 + 副标题）

---

### 批次 3：学习记录写入与列表（P0）

**目标**：完成闯关后自动保存记录；「我的」页展示真实历史列表。

**依赖**：批次 1、批次 2

#### 功能需求

| ID | 需求 | 说明 |
|----|------|------|
| U3-01 | 自动保存学习记录 | 用户完成全部题目并生成报告后，自动写入一条学习记录 |
| U3-02 | 记录摘要字段 | 每条记录包含：标题、完成时间、用时、正确率、答对题数/总题数 |
| U3-03 | 学习记录列表 | 「我的」页展示当前用户的历史记录，按时间倒序 |
| U3-04 | 列表分页或限量 | 首屏展示最近 N 条（如 20 条），支持「全部」查看完整列表 |
| U3-05 | 学习统计汇总 | 汇总并展示：累计闯关次数、平均正确率、累计学习时长 |
| U3-06 | 匿名不写入 | 未登录用户完成闯关不产生个人历史记录 |

#### 业务规则

- 仅**完成全部题目并成功生成报告**的会话才记为一条学习记录
- 中途退出、生成失败、答题未完成的不写入历史
- 记录标题来源：优先使用题目集标题；若无则截取学习文本前 20 字
- 统计指标随新记录增加实时更新
- 平均正确率 = 所有已完成记录正确率的算术平均（保留整数百分比展示）
- 学习记录持久化至 MySQL

#### 验收标准

- [ ] 登录用户完成一次闯关后，「我的」页出现对应记录
- [ ] 记录显示的时间、用时、正确率、题数与报告页一致
- [ ] 三项统计数字随记录变化而更新
- [ ] 匿名用户闯关后，「我的」页无新增记录（或提示登录后同步）
- [ ] 点击「全部」可查看超出首屏的完整记录列表

#### 原型对应

- ⑪ 我的页统计三格 + 学习记录列表
- ⑬ 报告页「答完啦，记录已保存」提示

---

### 批次 4：学习记录详情（P1 · 高优先级）

**目标**：用户可查看单次学习的完整复盘信息。

**依赖**：批次 3

#### 功能需求

| ID | 需求 | 说明 |
|----|------|------|
| U4-01 | 记录详情页 | 从「我的」列表点击进入单次学习详情（二级页，隐藏 TabBar） |
| U4-02 | 详情基础信息 | 展示标题、正确率、答对/总题、用时、完成时间 |
| U4-03 | 错题列表 | 展示本次答错的题目：题干、用户答案、正确答案 |
| U4-04 | AI 总结 | 展示本次学习报告中的 AI 总结文案 |
| U4-05 | 再练一次 | 详情页提供「再练一次」按钮，基于同一题目集重新闯关 |
| U4-06 | 返回导航 | 支持返回「我的」列表 |

#### 业务规则

- 详情数据来源于该次学习记录快照，不随题库后续变化而改变
- 「再练一次」创建新的练习会话，产生新的学习记录（不覆盖原记录）
- 全对时错题区域展示空状态（如「本次无错题」）

#### 验收标准

- [ ] 从「我的」点击任一条记录，进入详情页
- [ ] 详情页数据与当时报告页一致
- [ ] 详情页无底部 TabBar（二级页）
- [ ] 「再练一次」可进入答题流程并完成新一轮闯关

#### 原型对应

- ⑫ 学习记录详情页

#### 本次不做

- 「加入错题强化 · P1」按钮仅保留占位或隐藏

---

### 批次 5：题库（P1 · 高优先级）

**目标**：管理用户历史生成的题目集，支持重复练习。

**依赖**：批次 3（题目集在学习记录写入时一并创建）

#### 功能需求

| ID | 需求 | 说明 |
|----|------|------|
| U5-01 | 题目集自动创建 | 用户首次完成某次 AI 出题闯关后，生成一个题目集条目 |
| U5-02 | 题库列表 | 「题库」Tab 展示当前用户的题目集列表 |
| U5-03 | 题目集摘要 | 每条展示：标题、题目数量、题型说明、生成日期、练习状态 |
| U5-04 | 练习状态标识 | 区分「未练习」「已练过」、最近正确率（如 62%） |
| U5-05 | 开始闯关 | 对未练习的题目集，可「开始闯关」进入答题 |
| U5-06 | 再练一次 | 对已练习的题目集，可「再练一次」重新答题 |
| U5-07 | 查看题目 | 可查看题目集内题目列表（题干 + 选项，不展示答案） |
| U5-08 | 匿名空状态 | 未登录时展示引导登录或空状态，不展示 Mock 数据 |

#### 业务规则

- 同一来源文本多次出题生成不同题目集（每次 AI 出题独立一条）
- 题目集归属当前登录用户，不可访问他人题目集
- 「再练一次」与「开始闯关」均基于已有题目重新创建练习会话，不重新调用 AI 出题
- 练习状态根据该题目集下最近一次完成记录更新
- 题目集持久化至 MySQL

#### 验收标准

- [ ] 完成一次闯关后，「题库」出现对应题目集
- [ ] 题目集 meta 信息（题数、日期）正确
- [ ] 「开始闯关」「再练一次」可进入答题并完成
- [ ] 「查看题目」可浏览题干与选项
- [ ] 未登录时不展示 V1 Mock 演示数据

#### 原型对应

- ⑩ 题库列表页

#### 本次不做

- 顶部分类筛选（语文/历史/英语）— 仅展示「全部」
- 「错题强化 · P1」按钮 — 占位不实现

### 批次 6：流程串联与体验收尾（P2 · 中优先级）

**目标**：打通各 Tab 与主流程之间的导航与状态衔接。

**依赖**：批次 3、批次 4、批次 5

#### 功能需求

| ID | 需求 | 说明 |
|----|------|------|
| U6-01 | 首页「继续上次」 | 闯关 Tab 展示最近一次未完成或最近学习的会话摘要 |
| U6-02 | 继续学习 | 点击「继续上次」可恢复到对应进度（未完成）或快速再练（已完成） |
| U6-03 | 报告页保存提示 | 答完后展示「记录已保存」类提示（登录用户） |
| U6-04 | 报告页引导 | 提供「去我的查看记录」按钮，跳转「我的」Tab |
| U6-05 | 欢迎页文案更新 | 将「匿名学习 · 不登录 · V1」更新为反映登录能力的文案 |
| U6-06 | 输入页脚注更新 | 将「答完可在我的查看记录 · P1」更新为真实能力描述 |
| U6-07 | 登录后数据一致性 | 各 Tab 切换后数据与登录态保持一致，无残留 Mock |

#### 业务规则

- 「继续上次」优先级：未完成会话 > 最近完成会话
- 未完成会话定义：已生成题目、答题进度 > 0 且 < 总题数
- 报告页对匿名用户不展示「记录已保存」，可展示「登录后保存记录」引导

#### 验收标准

- [ ] 有未完成会话时，首页显示对应卡片与进度
- [ ] 报告页（登录用户）有保存成功提示，点击可跳转「我的」
- [ ] 欢迎页、输入页文案不再引用 V1 匿名限定表述
- [ ] 全链路无 Mock 数据残留

#### 原型对应

- ⑨ 首页「继续上次」
- ⑬ 报告页引导去「我的」

## 六、数据概念（需求层）

以下为业务实体，描述需要持久化的关系型数据（存储于 MySQL，表结构见方案设计文档）。

### 6.1 用户（User）

| 字段 | 说明 |
|------|------|
| 用户标识 | 系统内唯一 ID |
| 微信 OpenID | 微信身份关联 |
| 昵称 | 展示名称（支持用户自定义） |
| 头像 | 头像 URL 或默认 |
| 注册时间 | 首次登录时间 |

### 6.2 题目集（QuestionSet）

| 字段 | 说明 |
|------|------|
| 题目集标识 | 唯一 ID |
| 所属用户 | 创建者 |
| 标题 | 展示用短标题 |
| 原始学习文本 | 用户输入内容 |
| 题目列表 | AI 生成的完整题目 |
| 知识点 | AI 提取的知识点 |
| 题目数量 | 题数 |
| 创建时间 | 生成时间 |

### 6.3 学习记录（StudyRecord）

| 字段 | 说明 |
|------|------|
| 记录标识 | 唯一 ID |
| 所属用户 | 学习者 |
| 关联题目集 | 本次练习基于哪套题 |
| 正确率 | 百分比 |
| 答对题数 | 整数 |
| 总题数 | 整数 |
| 学习时长 | 秒 |
| 错题快照 | 错题列表 |
| AI 总结 | 报告摘要 |
| 完成时间 | 闯关完成时刻 |

### 6.4 实体关系

```
用户 1 ── N 题目集
用户 1 ── N 学习记录
题目集 1 ── N 学习记录
```
