# 《AI 互动学习闯关小程序》方案设计文档计划（首版可直接开发）

## Summary

- 文档目标锁定为一份“可直接开干”的首版方案，不写成泛泛而谈的选型分析。
- 首版只覆盖最短核心闭环：`文本粘贴输入 => AI 解析知识 => AI 生成题目 => 用户逐题作答 => AI 生成学习报告`。
- 已确认的关键决策：
  - 后端路线：`Python`
  - 模型供应商：`DeepSeek`
  - 首版输入范围：`只做文本粘贴`
- 文档主线要突出“小程序技术选型对比”，但最终必须收敛到一条推荐路线，避免 implementation 时继续摇摆。

## Key Changes

### 1. 技术选型章节要这样写

- 对比 3 条小程序路线：
  - `微信原生小程序`
  - `Taro 4 + React + TypeScript`
  - `uni-app(Vue3)`
- 推荐结论写死为：`Taro 4 + React + TypeScript`
- 推荐理由：
  - 比原生方案更适合独立开发者快速迭代
  - 比 uni-app 更适合把前端逻辑写成清晰的组件和状态流
  - 保留后续扩到 H5/其他端的可能，但首版仍只发微信小程序
  - 官方文档已明确支持 React 路线与 Skyline 相关配置，适合作为 2026 年首版工程基座
- 结论里要明确：
  - `Skyline` 作为“可选性能增强”，不是首版强依赖
  - 首版不要因为追求 Skyline/worklet 复杂动画而推高风险
  - 首版 UI 以轻量、稳定、可联调为优先

### 2. 系统架构章节要围绕“最短闭环”展开

- 前端：`Taro 4 + React + TypeScript + Zustand`
- 后端：`FastAPI + Pydantic + Uvicorn` todo: AI 大模型的对接使用 Python 的 LangChain 框架
- AI 编排：`LangChain + DeepSeek`
- 会话存储：首版使用`进程内存 + 本地文件兜底`，不先上 MySQL
- 文档里要明确前后端职责边界：
  - 小程序只负责输入、答题交互、展示报告
  - 后端负责知识提取、题目生成、答案校验、报告生成
  - AI 输出必须走结构化 JSON 校验，不能直接信任模型自然语言

### 3. 核心业务流程章节要写成可实现流程

- 首版固定 4 个页面/阶段：
  - 输入页
  - 生成中页
  - 答题页
  - 报告页
- AI 流程拆成 4 个独立步骤：
  - 知识提取
  - 题目生成
  - 单题讲解生成
  - 报告生成
- 题型只支持：
  - `单选题`
  - `判断题`
- 每道题必须包含：
  - `题干`
  - `选项`
  - `标准答案`
  - `解析`
  - `sourceEvidence`
- `sourceEvidence` 作为首版强约束，用于降低 AI 幻觉风险

### 4. 接口与数据结构章节要定死

- `POST /sessions`
  - 输入：`sourceText`、`questionCount`
  - 输出：`sessionId`、`status`
- `GET /sessions/{id}`
  - 输出：解析/出题状态、知识点、题目列表
- `POST /sessions/{id}/answers`
  - 输入：`questionId`、`selectedAnswer`
  - 输出：`isCorrect`、`correctAnswer`、`explanation`、`sourceEvidence`
- `GET /sessions/{id}/report`
  - 输出：`accuracy`、`wrongQuestions`、`weakPoints`、`summary`、`durationSeconds`

需要在文档中定义的核心类型：

- `StudySession`
- `KnowledgePoint`
- `Question`
- `AnswerRecord`
- `StudyReport`

### 5. 开发流程章节要按阶段写，不先碰登录/数据库

- Phase 0：跑通后端 AI 题目生成接口
- Phase 1：接入小程序输入页和答题页，形成完整闭环
- Phase 2：补报告页、异常处理、JSON 校验重试
- Phase 3：补本地会话记录、埋点、成本控制
- 明确后置项，不进入首版开发：
  - 登录注册
  - 云数据库/MySQL
  - 排行榜/PK
  - 家长端
  - 复杂题型
  - 视频解析
  - 分享裂变系统

## Test Plan

- 输入 300 到 800 字中文学习内容，可以稳定生成 5 到 10 道可答题目
- 题目结构始终合法，单选题答案唯一，判断题值域固定
- 用户能完整走通：输入 -> 生成 -> 答题 -> 报告
- 至少 80% 题目带有可追溯的 `sourceEvidence`
- 模型返回异常 JSON 时，后端能自动重试或返回可理解错误
- 输入过短、空内容、噪声内容时，前后端都能给出明确提示
- 连续两次不同内容生成，不发生会话串题
- 成本控制测试：
  - 限制输入长度
  - 限制题目数量
  - 限制单次报告生成 token 消耗

## Assumptions

- 这份文档的“首版”定义为 `MVP V1`，不是长期全量产品蓝图。
- 文档要重点回答 4 件事：
  - 为什么选这条小程序路线
  - 如何最快跑通核心业务
  - 系统如何分层
  - 后续如何安全扩展
- 首版默认不接数据库；若后续需要学习历史，再升级到 `MySQL`。
- 首版默认只支持文本输入；`PDF/网页链接` 进入下一阶段，不写入首版实现范围。
- 技术选型对比应基于 2026-05-18 可查的官方资料，并在文档中附参考链接：
  - Taro React 总览：[https://docs.taro.zone/docs/react-overall](https://docs.taro.zone/docs/react-overall)
  - Taro Skyline：[https://docs.taro.zone/docs/skyline/](https://docs.taro.zone/docs/skyline/)
  - uni-app CLI 快速上手：[https://uniapp.dcloud.net.cn/quickstart-cli.html](https://uniapp.dcloud.net.cn/quickstart-cli.html)
  - uni-app 多端/条件编译：[https://uniapp.dcloud.net.cn/tutorial/platform.html](https://uniapp.dcloud.net.cn/tutorial/platform.html)
